# Check whether a criticism survives scrutiny

Use this for consequential concerns and for resolving disagreement. It works with one reviewer; multiple agents are optional and require authorization. It is not a numerical scoring system.

## Before retaining a major comment

1. **State the exact proposition.** “Images from the same participant cross the reported training/test boundary” is testable; “validation is weak” is not specific enough.
2. **Locate direct evidence.** Record the actual section, table, code/configuration, or contradiction. An issue pattern learned from another paper is only a hypothesis to check.
3. **Look for a reasonable defense.** Could the relevant analysis be paired, the claim deliberately local, the mechanism presented as hypothetical, or the missing detail present in a supplement? Check the available materials rather than invent that defense as fact.
4. **Separate uncertainty from error.** If the analytical unit is not stated, request it. If the methods explicitly treat nested replicates as independent, explain the demonstrated mismatch. Confidence concerns the support for this criticism, not a subjective publication score.
5. **Test consequence.** Identify which claim or uncertainty estimate is affected. Demote or withdraw peripheral preferences; distinguish required fixes from optional extensions.
6. **Choose a proportionate remedy.** Clarification, correction, sensitivity analysis, or narrowing may suffice. Explain why new data would be necessary if recommending it. If no adequate remedy is evident within competence, say so.
7. **Record the disposition.** Retain, revise to a question, reduce priority, or withdraw, with the reason in the private workbook. A withdrawn false alarm should not survive in the author report as insinuation.

## When sources disagree

Preserve the original concern IDs and their provenance before merging. Merge only concerns with the same underlying failure, claim, and remedy; superficially similar concerns about different outcomes may remain separate. Do not let repetition inflate severity.

Classify disagreement as factual, methodological, scope/venue-related, or unresolved expertise. Resolve factual disputes against manuscript evidence, methodological disputes against the relevant design and justified criterion, and scope disputes against the actual claim and venue rules. Preserve uncertainty where evidence is insufficient; request specialist assessment when central.

If an authorized panel was used, disclose actual provenance when known: model/provider, invocation context, visibility of peer reports, and tools. Distinct personas using the same model can share errors. Never label generated personas as actual human experts or treat majority agreement as empirical confirmation.

## Revision transitions

- **Open → resolved:** the revised material or justified response addresses the scientific consequence; cite where.
- **Open → partly resolved:** some consequence remains; state the remaining bounded action.
- **Open → no longer applicable:** the problematic claim/analysis was removed and downstream statements were reconciled.
- **Resolved → open:** new evidence or a later consequential change defeats the remedy; explain why this is not moving the criteria.

Record the submitted version and preserve earlier status/reason. A response letter is a claim about a change, not proof that it occurred. If an analysis is described but data/code were not executed, say “reported remedy addresses the concern; numerical reproduction not performed,” not “analysis verified.”
